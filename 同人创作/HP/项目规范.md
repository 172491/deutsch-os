# HP 同人项目规范

本文件是新会话处理《Eleanor / Alexis》重修工作的前置规范。它约束“如何读取、如何判断、如何写入”，不替代具体剧情设定。

## 一、读取顺序

处理任何涉及仓库、人物、关系、能力、分部修改或原稿的问题时，必须按以下顺序读取：

1. `README.md` 与本文件。
2. `08_决策记录/已确认设定.md`；若问题涉及尚未统一的事项，同时读 `08_决策记录/待裁决冲突.md`。
3. 当前问题直接相关的总体结构、人物关系、能力档案或分部修改文件。
4. 若需要判断“原稿实际写了什么”，必须读取 `01_原稿/26.10.2/` 对应原稿，不得用修改稿或讨论摘要代替原稿。
5. 只有需要追溯理由时才读取 `09_讨论存档/`。

不得声称读取、核对或确认未实际读取的文件。

## 二、资料权威顺序

发生冲突时，按以下顺序处理：

1. 作者明确确认并已写入 `08_决策记录/已确认设定.md` 的内容。
2. 当前有效的跨卷总表、关系总档案、能力总档案。
3. `06_分部修改方案/` 中该分部的当前有效版本。
4. `01_原稿/26.10.2/`：用于确认旧稿事实，不自动代表重修后的最终方案。
5. 历史讨论、AI 草稿、候选方案。

AI 草稿、建议稿、讨论中的试探性方案均不得自动升级为作者观点。

## 三、状态标签

新增设定应尽量标记以下状态之一：

- **已确认**：作者明确接受，可作为后续写作约束。
- **现行工作口径**：当前最高版本修改稿正在使用，但尚未上升为全局不可更改设定。
- **待裁决**：不同文件存在口径差异，或作者尚未最终决定。
- **已否决**：不得在后续方案中重新当作默认选项使用，除非作者明确推翻旧决定。

## 四、修改工作的基本原则

### 1. 关系、能力、剧情必须联动

能力发展不能只写“学会了什么”；必须追踪它由谁参与、谁能拒绝、谁拥有专业边界，以及它如何改变人物关系。关系变化也不能只写情感温度；必须落实到信息权、选择权、指挥权、合作方式和具体剧情选择。

### 2. 不以 Eleanor / Alexis 为世界中心

霍格沃茨、魔法部、媒体、纯血家族、学生社会、第一次战争遗产、商业与技术网络等必须拥有独立目标、资源、信息差和行动。群像人物不能只在主角需要时出现。

### 3. 强大不等于全专业碾压

Eleanor / Alexis 可以具有极高学习能力、魔法天赋和跨领域整合能力，但发明、治疗、魔药、战斗、精神魔法、时间魔法等领域必须存在专业边界。协作不能写成“别人帮助主角完成她本来就能独立完成的事”。

### 4. 伤害必须产生因果

身体受伤、自毁、吐血、昏迷等不能替代人物后果。若删除某处身体伤害后，人物判断、关系状态、制度后果完全不变，则应优先降低或删除该伤害。

### 5. 严格维护信息边界

每个角色只能依据自己实际经历、被告知或合理调查得到的信息行动。不得为了让对话更聪明而让角色获得读者信息；不得让其他人物知道 Eleanor 的平行世界记忆，除非后续明确建立新的知情事件。

## 五、术语与叙事口径

- 对 Eleanor / Alexis 而言，她拥有的是另一个真实平行世界中已经发生过的一段历史记忆，且严格受 Harry 七学年视角限制。不要在人物内部叙事中使用“原著剧情”“小说剧情”“剧情保障”等外部词。
- `Alexis Weston` 与 `Eleanor Potter` 都是真实的她；不同阶段可按人物知情范围和自我认同使用不同名字，不把其中一个降格为虚假人格。
- 处理原稿与重修稿时，必须区分“旧稿事实”“现行修改方案”“已确认最终设定”。

## 六、版本管理

- `06_分部修改方案/总施工索引.md` 记录每一部当前有效版、依赖与下一步。
- 同一分部存在多个版本时，必须说明新版本新增、废弃和继承了什么；不得默认新版本全文覆盖旧版所有未提及内容。
- 跨卷设定发生变化时，先更新 `08_决策记录/` 与 `02_总体结构/跨卷连续性总表.md`，再回写各分部文件。

## 七、新会话最低读取集

若只需要快速继续工作，最低读取集为：

`README.md` → `项目规范.md` → `08_决策记录/已确认设定.md` → 当前问题对应总档案 → 当前分部有效修改稿 → 必要的原稿章节。
