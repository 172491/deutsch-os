# 项目档案｜后续项目与第六部安全装置约束

> 本文件只固定已经明确的需求与禁区，不擅自确定最终装置外形。

## 一、原“健康监测手表”处理结论

原稿第六部使用 Alexis 自己的血培养材料制作装置，让 Draco 随时查看她的位置和心率；Draco 又要求反向制作一块。

**这一现行形式已否决。**

问题不在“情侣之间不能有安全设备”，而在于它把成熟伴侣关系重新写回：

- 默认持续定位；
- 默认身体数据可见；
- 用血液绑定强化不可撤回性；
- 把“我爱你”直接转换成“我有权一直知道你在哪里、身体怎样”；
- 双向监控被当成平等，而不是双方都失去边界。

这与第五部已经建立的“知道 ≠ 接管、爱 ≠ 替对方决定”冲突。

## 二、第六部仍然成立的真实需求

战争期确实存在以下问题：

- 失联；
- 单独行动；
- 重伤后无法主动求救；
- 敌方隔离通讯；
- 同伴需要判断“继续等 / 撤退 / 请求成年人或 Phoenix 支援”。

因此可以保留“安全协作装置”方向，但必须重新设计权限。

## 三、替代装置必须满足的权限原则

1. **日常默认不持续定位。**
2. **数据最小化。** 只传递完成行动所需的状态，不把完整身体数据长期开放给另一人。
3. **主动 check-in 优先。** 正常情况下由使用者主动确认安全 / 需要帮助。
4. **紧急模式单独定义。** 只有在明确条件触发或使用者主动开启时扩大信息范围。
5. **权限可撤回。** 不能因为血液、灵魂或不可逆绑定让使用者失去退出权。
6. **一方收到警报不等于获得指挥权。** 接收者仍需按事先约定的行动协议处理。
7. **多人系统优先于情侣专属。** 如果装置真的是战争安全工具，它应有可能服务小队 / 家人 / Phoenix，而不是只有恋人才能使用。

## 四、当前可继续探索的功能需求

这些是需求，不是已确定成品：

- 短时任务信标：执行危险任务时主动开启，任务结束自动关闭；
- 状态分级：安全 / 需要联系 / 需要支援，而非连续心率流；
- 失联计时：超过双方预先约定时间未 check-in 才触发升级；
- 单次紧急坐标：只在主动求救或严重失能条件下发送最后位置；
- 小队撤退协议：设备只负责提示协议触发，不替任何人决定是否服从；
- 医疗摘要：由 Pomfrey /专业者定义最小必要字段，而非把生理监控设计交给恋人。

## 五、与关系线的结合

第六部如果使用这类装置，真正应该检验的是：

- Eleanor 能不能在出发前告诉别人，而不是留下一个设备让别人追踪；
- Draco 能不能收到危险信号后按双方协议行动，而不是因恐惧直接接管；
- Harry / Snape / Sirius 是否拥有不同职责，而不是所有人都看同一个“Eleanor 状态面板”；
- 技术失效时，关系是否仍能依靠判断、承诺和团队结构运作。

最终装置应在第六部正式修改方案中定型。
